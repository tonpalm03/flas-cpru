# FastCPRU Plan Web Portal (ระบบแผนและบริหารงบประมาณ)

เว็บพอร์ทัลสำหรับบริหารงบประมาณและโครงการ พัฒนาขึ้นด้วย **React 19 + TypeScript + Vite + Tailwind CSS v4** เชื่อมต่อกับ **Supabase (PostgreSQL)** ออกแบบโครงสร้างและ UI อ้างอิงจาก Figma Mockup เต็มรูปแบบ โดยโฟกัสที่โมดูล **`feature_plan`**

---

## 🚀 วิธีการเริ่มต้นใช้งาน (Quick Start)

```bash
# 1. เข้าสู่โฟลเดอร์ web (จากรากของ repo)
cd web

# 2. ติดตั้ง Dependencies (ทำครั้งแรก)
npm install

# 3. เริ่มรัน Development Server
npm run dev
```

เปิดเว็บเบราว์เซอร์ที่: **`http://localhost:5173`**

หน้าเว็บเรียก backend (FastAPI) ที่ `http://127.0.0.1:8001/api/v1` (เปลี่ยนได้ด้วย `VITE_BACKEND_API_URL`) — เปิด backend ก่อน และสร้างบัญชีทดสอบครั้งแรก:

```bash
cd backend
./venv/Scripts/python.exe scripts/manage_users.py seed-demo   # บัญชี teacher, teacher2, officer, plan_head, dean, head รหัส demo-pass-2570
./venv/Scripts/python.exe -m uvicorn main:app --port 8001 --reload
```

### ทดสอบ

| ชุด | คำสั่ง | ตรวจอะไร |
|---|---|---|
| backend | `./venv/Scripts/python.exe -m pytest -q` (ใน `backend/`, ครั้งแรก `pip install -r requirements-dev.txt`) | กติกา workflow, เอกสาร Word, งบ, สิทธิ์, API, สำรองข้อมูล |
| หน้าเว็บ | `npx tsc --noEmit -p tsconfig.json && npm run build` (ใน `web/`) | type และการ build |
| ทั้ง flow ในเบราว์เซอร์ | `npm run test:e2e` (ใน `web/`) | login → เสนอโครงการ → ตรวจ → เดินเซ็น → สแกน → เบิกจ่าย → ปิดโครงการ, จัดการผู้ใช้, หน้างานเจ้าหน้าที่ |

- `npm run test:e2e` เปิด backend (ฐานข้อมูลใหม่ทุกครั้งที่ `web/e2e/.data` + บัญชีทดสอบ) ที่ port 8011 และหน้าเว็บที่ port 5174 เอง แยกจากเครื่องพัฒนา — port ทั้งสองต้องว่าง
- ในเครื่อง Windows ใช้ Microsoft Edge ที่ติดตั้งอยู่; ที่อื่นตั้ง `CI=true` แล้วติดตั้ง Chromium ด้วย `npx playwright install chromium`; Python ของ backend เลือกจาก `E2E_PYTHON` หรือ `backend/venv`
- ชุดทดสอบอยู่ใน `web/e2e/*.spec.ts` (ตัวช่วย login/สร้างโครงการผ่าน API อยู่ใน `web/e2e/support/`) — เพิ่มฟีเจอร์ใหม่ให้เพิ่มเทสต์ที่นี่ด้วย
- GitHub Actions (`.github/workflows/plan.yml`) รันทั้งสามชุดทุก pull request ที่แก้ `backend/` หรือ `web/`; ถ้า e2e ล้ม ดาวน์โหลดรายงาน (trace + ภาพหน้าจอ) จาก artifact `playwright-report`

## 📄 Workflow เอกสารโครงการ

ผู้ใช้ login ด้วยชื่อผู้ใช้/รหัสผ่านของระบบแผน (ชั่วคราว ระหว่างรอระบบ login กลางของทีม — เปลี่ยนได้ที่ `backend/auth.py` และ `web/src/lib/currentUser.ts`) ทุก request แนบ `Authorization: Bearer <token>` อาจารย์เห็นและแก้ได้เฉพาะโครงการของตัวเอง บทบาทอื่นเห็นทุกโครงการของคณะ

| สถานะ | ความหมาย | ใครทำอะไร |
|---|---|---|
| `DRAFT` แบบร่าง | อาจารย์บันทึกร่างได้ทุกขั้นตอน | อาจารย์แก้ไข / ส่งให้เจ้าหน้าที่ตรวจ |
| `PENDING_REVIEW` รอเจ้าหน้าที่ตรวจ | | เจ้าหน้าที่ดูตัวอย่างเอกสาร, แก้แทน, อนุมัติ / ตีกลับ / ไม่อนุมัติ (ต้องระบุเหตุผล) |
| `REVISION_REQUESTED` ตีกลับแก้ไข | อาจารย์เห็นเหตุผลในหน้าโครงการและหน้าแก้ไข | อาจารย์แก้แล้วส่งใหม่ |
| `REJECTED` ไม่อนุมัติ | สิ้นสุด | |
| `APPROVED_FOR_PRINT` อนุมัติแล้ว รอพิมพ์/เซ็น | ระบบสร้าง .docx ตามแบบฟอร์มปีงบ | อาจารย์ดาวน์โหลดไปพิมพ์และเซ็น |
| `WAITING_FOR_SIGNATURES` อยู่ระหว่างเดินเซ็น | เอกสารกระดาษ: อาจารย์ → หัวหน้างานแผน → คณบดี | เจ้าหน้าที่ติ๊กทีละขั้นพร้อมวันที่ (ย้อนได้) |
| `WAITING_FOR_SCAN` เซ็นครบ รอสแกน | | เจ้าหน้าที่อัปโหลดสแกน (PDF/JPG/PNG ไม่เกิน 20 MB) — ระบบล็อกงบรายกิจกรรมและแจ้งอาจารย์อัตโนมัติ |
| `COMPLETED_WITH_SCAN` เสร็จสมบูรณ์ | | อาจารย์ดาวน์โหลดฉบับสแกน / เจ้าหน้าที่บันทึกเบิกจ่ายและปิดโครงการ |
| `COMPLETED` ปิดโครงการแล้ว | งบที่เหลือคืนวงเงินสาขา | บันทึกเบิกจ่ายเพิ่มไม่ได้ |

- ขั้นตอนลงนามเก็บในตาราง `plan_signing_steps` (เพิ่มอธิการบดี = เพิ่มแถว, ให้ลงนามในระบบ = เปลี่ยน `mode` เป็น `IN_SYSTEM`)
- ข้อมูลที่เปลี่ยนตามปีงบ (แบบฟอร์ม Word, แหล่งงบ, หมวดรายจ่าย, แผนยุทธศาสตร์) อยู่ที่ `backend/fiscal_years/` — ดูวิธีเปิดปีใหม่ใน [backend/fiscal_years/README.md](../backend/fiscal_years/README.md)
- ออกแบบไว้ใน `docs/superpowers/specs/2026-10-14-plan-document-workflow-design.md`

## 🏫 เปิดให้คณะทดลองใช้ (pilot)

ใช้ฐานข้อมูลใหม่แยกจากเครื่องพัฒนา และไม่มีข้อมูลตัวอย่าง:

```bash
cd backend
# ตั้งครั้งเดียวใน shell ที่ใช้รัน (หรือใส่ใน .env ของเครื่อง server)
export FASTCPRU_DB_PATH=/path/to/pilot/fastcpru_pilot.db
export FASTCPRU_UPLOADS_DIR=/path/to/pilot/uploads
export FASTCPRU_SEED_DEMO=0

# สร้างบัญชีจริงจาก CSV (UTF-8): username,display_name,role,department,position,phone,password
# ช่อง password ว่าง = สุ่มรหัสให้; --out = ใบรายชื่อพร้อมรหัสเริ่มต้นไว้แจก (ตัวอย่างไฟล์: scripts/pilot_users_sample.csv)
./venv/Scripts/python.exe scripts/manage_users.py import users.csv --out credentials.csv
./venv/Scripts/python.exe scripts/manage_users.py list

# เปิดให้เครื่องอื่นในคณะเข้าถึง (ไม่ใช้ --reload)
./venv/Scripts/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8001
```

```bash
cd web
npm run build
npm run preview -- --host --port 5173
```

- หน้าเว็บเรียก backend ที่เครื่องเดียวกับที่เปิดหน้าเว็บ (port 8001) ให้เอง มือถือ/เครื่องอื่นเปิด `http://<ip-เครื่อง-server>:5173` ได้เลย
- ถ้า backend อยู่คนละเครื่องหรือคนละ port ให้ใส่ `VITE_BACKEND_API_URL=http://<เครื่อง>:<port>/api/v1` ตอน `npm run build`

- **บทบาทในไฟล์ CSV:**
  - `teacher` อาจารย์
  - `officer` เจ้าหน้าที่แผน
  - `plan_head` หัวหน้างานแผน
  - `dean` คณบดี
  - `head` ประธานสาขา
  - ช่อง `department` ของอาจารย์คือชื่อสาขา ตรงกับวงเงินจัดสรรของสาขา
- **จัดการผู้ใช้ในหน้าเว็บ:** เจ้าหน้าที่แผนใช้เมนู "จัดการผู้ใช้งาน" ได้เอง ทั้งเพิ่มทีละคน นำเข้าจาก CSV (มีปุ่มดาวน์โหลดแบบฟอร์ม) แก้ข้อมูล ตั้งรหัสใหม่ และปิดหรือเปิดบัญชี รหัสเริ่มต้นแสดงครั้งเดียวพร้อมใบรายชื่อไว้แจก คำสั่ง `manage_users.py` ใช้แค่ตอนสร้างบัญชีเจ้าหน้าที่แผนคนแรก
- **รหัสผ่าน:** แจกรหัสเริ่มต้นให้แต่ละคน แล้วให้เปลี่ยนเองที่ปุ่ม "เปลี่ยนรหัสผ่าน" มุมขวาบน ถ้าลืมรหัส ให้เจ้าหน้าที่กด "ตั้งรหัสใหม่" ในหน้าจัดการผู้ใช้งาน
- **session:** อายุ 12 ชั่วโมง หลังจากนั้นต้อง login ใหม่
- **วงเงินจัดสรรของสาขาปีงบ 2570:** ฐานข้อมูล pilot เริ่มต้นไม่มีวงเงิน เจ้าหน้าที่แผนตั้งเองที่เมนู "จัดสรรงบสาขา" (ถ้ายังไม่ตั้ง ตอนอนุมัติโครงการจะมีคำเตือนว่าสาขายังไม่มีวงเงิน แต่ยังอนุมัติได้)
- **อัปเดต backend ที่ติดตั้งไว้แล้ว:** รัน `./venv/Scripts/python.exe -m pip install -r requirements.txt` อีกครั้ง (รอบคุมงบเพิ่ม `openpyxl` สำหรับไฟล์ Excel รอบนำเข้าไฟล์สแกนเพิ่ม `anthropic` และ `pypdf`)
- **นำเข้าไฟล์สแกน (PDF):** ต้องมี key ใน `backend/.env` อย่างใดอย่างหนึ่ง แล้วเปิด backend ใหม่ ถ้าไม่มีเลย ปุ่มนำเข้าไฟล์ยังรับไฟล์ Word ได้ตามเดิม ส่วนไฟล์ PDF จะขึ้นว่ายังไม่ได้ตั้งค่า
  - `GEMINI_API_KEY=...` ใช้ Gemini (`gemini-3.8-flash`) ซึ่งเป็น key ที่ใช้กับหน้าแมปแม่แบบอยู่แล้ว
  - `ANTHROPIC_API_KEY=...` ใช้ Claude (`claude-opus-5-5`) ถ้ามีทั้งสอง key ระบบจะใช้ Claude
  - AI อ่านทีละหน้า แล้วใช้ตัวอ่านเดียวกับไฟล์ Word เติมข้อมูลลงฟอร์ม (`backend/services/proposal_scan.py`)
  - เนื้อหาเอกสารถูกส่งไปประมวลผลที่ผู้ให้บริการ และมีค่าใช้จ่ายตามจำนวนหน้า จำนวน token ของแต่ละหน้าอยู่ใน log ของ backend
  - ถ้าใช้ Gemini แบบไม่เสียเงิน (free tier) Google อาจนำเนื้อหาที่ส่งไปใช้ปรับปรุงบริการ สำหรับเอกสารจริงควรใช้แบบเสียเงิน
- **สำรองข้อมูล:** ใช้ `scripts/backup_data.py` ทุกวัน (ดูหัวข้อถัดไป)
- **Windows server:** เปิด firewall ให้ port 8001 และ 5173

### เปิดให้ดูผ่านลิงก์ชั่วคราว (สาธิต) และติดตั้งเป็นแอปบนมือถือ

ยังไม่มี server ก็สาธิตได้ โดยใช้เครื่องนี้เป็น server ชั่วคราว:

1. ดับเบิลคลิก `scripts\demo-link.cmd` (อยู่ที่รากของ repo) สคริปต์จะทำ 3 อย่าง:
   - build หน้าเว็บ
   - เปิด backend และหน้าเว็บ ถ้ายังไม่ได้เปิด
   - แสดงลิงก์
   - **ข้อมูลที่ใช้ (ค่าเริ่มต้น): ฐานข้อมูลสาธิต** แยกจากข้อมูลจริง อยู่ที่ `backend\demo\`
     - สร้างให้เองครั้งแรกด้วย `backend\scripts\seed_showcase.py`
     - มีบัญชีตัวอย่างทุกบทบาท และโครงการ 9 โครงการครบทุกขั้น (ร่าง, รอตรวจ, ตีกลับ, อนุมัติรอพิมพ์, เดินเซ็น, รอสแกน, งบพร้อมใช้พร้อมคำขอเบิกที่รอ, ปิดแล้ว)
     - รหัสผ่านสุ่มใหม่ทุกครั้งที่สร้าง ดูได้ที่ `backend\demo\demo-accounts.txt` (สคริปต์แสดงให้ตอนเริ่มด้วย)
     - ระบบสาธิตใช้ port 8101 / 5180 จึงไม่ชนกับเครื่องพัฒนา
   - **ตัวเลือก:**
     - `-ResetDemo`: ล้างแล้วสร้างข้อมูลสาธิตใหม่
     - `-RealData`: ใช้ข้อมูลจริงของเครื่องนี้ (port 8001 / 5173)
     - `-NoTunnel`: ไม่เปิดลิงก์สาธารณะ
     - เรียกแบบนี้: `powershell -ExecutionPolicy Bypass -File scripts\demo-link.ps1 -ResetDemo`
2. ลิงก์ที่ได้มี 2 แบบ:
   - **ในเครือข่ายเดียวกัน:** `http://<IP เครื่องนี้>:5173` ใช้ได้เมื่อมือถือต่อ Wi-Fi เดียวกัน แต่ Wi-Fi บางแห่งกันไม่ให้เครื่องเห็นกัน
   - **ลิงก์ https ชั่วคราว:** ใช้ได้ทุกที่รวมถึง 4G
     - ต้องมี `tools\cloudflared.exe` (ดาวน์โหลด `cloudflared-windows-amd64.exe` จาก github.com/cloudflare/cloudflared/releases แล้วเปลี่ยนชื่อ) ไม่ต้องสมัครบัญชี
     - หรือใช้ ngrok ที่ตั้งค่าบัญชีไว้แล้ว
3. **ติดตั้งเป็นแอป** ต้องใช้ลิงก์ https:
   - กดปุ่ม **"ติดตั้งแอป"** ในระบบ: ใต้กล่องเข้าสู่ระบบ, ปุ่มสีเหลืองบนแถบด้านบนของหน้าหลัก หรือแถบล่าง "เพิ่มเติม" → "ติดตั้งแอปลงมือถือ"
   - Android (Chrome): ปุ่มเปิดกล่องติดตั้งของเครื่องทันที (หรือเมนู ⋮ → "ติดตั้งแอป")
   - iPhone (Safari): ปุ่มแสดงวิธี — ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม"
   - ได้ไอคอนคณะ และเปิดเต็มจอเหมือนแอป
   - บนมือถือ เมนูอยู่ที่แถบล่าง ปุ่มย้อนกลับของเครื่องพากลับหน้าก่อนหน้าในระบบ (ฟอร์มที่ยังไม่บันทึกจะถามก่อนออก)
4. ระหว่างสาธิต เปิดหน้าต่างสคริปต์ค้างไว้และอย่าให้เครื่องหลับ ปิดหน้าต่าง = ลิงก์ใช้ไม่ได้

ข้อควรรู้:
- **ข้อมูลที่เห็น:** มาจากฐานข้อมูลของ backend เครื่องนี้
- **ลิงก์ https:** ใครมีลิงก์ก็เปิดหน้า login ได้ ใช้รหัสผ่านที่เดายาก และปิดเมื่อสาธิตเสร็จ
- **รหัสผิด:** ผิด 5 ครั้งติดกัน บัญชีนั้นจะรอ 15 นาที หรือให้เจ้าหน้าที่ตั้งรหัสใหม่
- **ที่อยู่ backend:** หน้าเว็บเรียก backend ผ่าน `/api/v1` ของที่อยู่เดียวกัน (`vite.config.ts` ส่งต่อไป port 8001) ลิงก์เดียวจึงใช้ได้ทุกเครื่อง
- **ส่วนแอปบนมือถือ:** `web/public/manifest.webmanifest`, `web/public/sw.js` และหน้า `offline.html` ไม่เก็บข้อมูลโครงการไว้ในเครื่อง

### สำรองและกู้คืนข้อมูล

```bash
cd backend
# สำรอง (ทำได้ขณะระบบเปิดอยู่) — เก็บไว้ 30 ชุดล่าสุด ควรเป็นคนละดิสก์กับเครื่อง server
./venv/Scripts/python.exe scripts/backup_data.py backup --dest D:/fastcpru-backups --keep 30
# ตรวจว่าชุดสำรองใช้กู้คืนได้ (integrity + checksum)
./venv/Scripts/python.exe scripts/backup_data.py verify D:/fastcpru-backups/fastcpru-20261016-020000
# กู้คืน: ปิด backend ก่อน; ถ้ามีข้อมูลอยู่ต้องใส่ --force (ของเดิมถูกเก็บไว้ข้างกันเป็น *.before-restore-<เวลา>)
./venv/Scripts/python.exe scripts/backup_data.py restore D:/fastcpru-backups/fastcpru-20261016-020000 --force
```

## 🗂️ งานของเจ้าหน้าที่ (แยกตามขั้นงาน)

เมนู "งานของเจ้าหน้าที่" แบ่งเป็นแท็บตามลำดับที่โครงการเดินไป แต่ละแท็บมีตัวเลขงานค้าง ช่องค้นหา และตัวกรองสาขา:

1. **รอตรวจ** — ตรวจรายละเอียด แก้แทนอาจารย์ อนุมัติ ตีกลับ หรือไม่อนุมัติ
2. **พิมพ์และเดินเซ็น** — แต่ละแถวบอกว่ารอใครลงนามและค้างมากี่วัน ปุ่มบันทึกการลงนามอยู่บนสุดของรายละเอียด
3. **รอสแกน** — ลากไฟล์สแกน (PDF/JPG/PNG ไม่เกิน 20 MB) มาวางที่แถวของโครงการ หรือคลิกเพื่อเลือกไฟล์ ระบบอัปโหลดทันที
4. **เบิกจ่าย / ปิดโครงการ** — ทะเบียนการเบิกจ่ายเปิดอยู่ในหน้าเดียวกัน และมีปุ่มปิดโครงการเมื่ออัปโหลดสแกนแล้ว
5. **ปิดแล้ว** และ **ทั้งหมด** — ดูย้อนหลัง

- งานค้างแต่ละหมวดดูจากตัวเลขบนแท็บของหน้านี้ — การ์ด 4 หมวดย้ายไปอยู่หน้าภาพรวมของอาจารย์ (ดูหัวข้อ "งานของฉัน")
- ตัวเลขบนเมนู = งานที่รอเจ้าหน้าที่ทำเอง (รอตรวจ + รอสแกน)
- หัวหน้างานแผน คณบดี และประธานสาขา เห็นหน้าเดียวกันแบบดูอย่างเดียว
- เจ้าหน้าที่ไม่มีเมนู "เสนอโครงการใหม่" และ "โครงการทั้งหมด": โครงการที่สร้างจะมีผู้สร้างเป็นเจ้าของ และส่งตรวจได้เฉพาะอาจารย์ ส่วนการดูโครงการทั้งหมดใช้แท็บ "ทั้งหมด" หรือช่องค้นหาด้านบน — สิทธิ์เปิดหน้าตามบทบาทอยู่ที่ `web/src/lib/pageAccess.ts` (ลิงก์ #hash ที่บทบาทนั้นเปิดไม่ได้จะกลับหน้าภาพรวม)
- **การเบิกจ่าย:** อาจารย์ขอเบิกและขอปิดโครงการในระบบ แล้วเจ้าหน้าที่แผนบันทึกเบิกตามเลขที่ฎีกา ตีกลับ หรือปิดโครงการ (ดูหัวข้อ "ขอเบิกและขอปิดโครงการ") ตัวเลขบนเมนูนับคำขอที่รอด้วย

ใช้กับอาจารย์ที่เขียนโครงการในแบบฟอร์ม Word ของมหาวิทยาลัย (.docx) ไว้ก่อนแล้ว ไม่ต้องพิมพ์ใหม่:

- **ที่ backend:**
  - โค้ดอยู่ที่ `backend/services/proposal_import.py` และ route คือ `POST /api/v1/projects/import-docx`
  - ใช้ได้กับอาจารย์ ประธานสาขา หัวหน้างานแผน และคณบดี ไม่เปิดให้เจ้าหน้าที่
  - ไฟล์ไม่เกิน 10 MB
- **เทสต์:**
  - เทสต์อยู่ที่ `backend/tests/test_proposal_import.py`
  - ครอบคลุมไฟล์ที่ระบบสร้างเอง แบบฟอร์มเปล่า และแบบฟอร์มที่จำลองว่าอาจารย์กรอกเอง

## 🗑️ ลบโครงการ (ย้ายไปถังขยะ)

ลบ = ซ่อนจากทุกหน้าแต่ยังเก็บประวัติไว้ เจ้าหน้าที่แผนกู้คืนได้ที่เมนู "ถังขยะ" (กลับไปสถานะเดิม)

| ใคร | ลบอะไรได้ | ต้องใส่เหตุผล |
|---|---|---|
| อาจารย์เจ้าของ | ร่างที่ยังไม่เคยส่ง ("ลบร่าง" ที่หน้าโครงการหรือใน "งานของฉัน") | ไม่ต้อง |
| อาจารย์เจ้าของ | โครงการที่ส่งแล้วแต่ยังไม่อนุมัติ (รอตรวจ / ถูกตีกลับ) — "ถอนโครงการ" | ต้อง |
| เจ้าหน้าที่แผน | โครงการที่ยังไม่อนุมัติ หรือไม่อนุมัติแล้ว เช่น ส่งซ้ำ ส่งผิด โครงการทดสอบ ("ลบโครงการ" ที่หน้าโครงการหรือหน้างานเจ้าหน้าที่) | ต้อง |

- หลังอนุมัติแล้วลบไม่ได้ เพราะมีไฟล์ให้พิมพ์ ลายเซ็น และงบผูกอยู่ ต้องย้อนตามขั้นตอนแทน
- รหัสโครงการที่ลบแล้วไม่ถูกใช้ซ้ำ
- ประวัติการลบและกู้คืนอยู่ใน audit log
- โค้ดอยู่ที่ `backend/services/project_trash.py` และ `web/src/components/plan/DeleteProjectButton.tsx`

## 📥 งานของฉัน (อาจารย์)

หน้าภาพรวมของอาจารย์มีการ์ด 4 ขั้นงาน (รอตรวจ / พิมพ์และเดินเซ็น / รอสแกน / เบิกจ่าย-ปิดโครงการ) นับเฉพาะโครงการของตัวเอง กดการ์ดเพื่อกรองรายการ "โครงการของฉัน" (กดซ้ำ = แสดงทั้งหมด) ตามด้วย "งานของฉัน":

- **เอกสารลงนามครบแล้ว พร้อมพิมพ์** — เมื่อเจ้าหน้าที่อัปโหลดสแกน จะมีป้าย "ใหม่" กด "เปิดดู / พิมพ์" เพื่อเปิดไฟล์ในแท็บใหม่แล้วสั่งพิมพ์ หรือกด "ดาวน์โหลด" (ป้ายหายเมื่อเปิดครั้งแรก)
- **ถูกตีกลับให้แก้ไข** — เห็นเหตุผล และปุ่มแก้ไขแล้วส่งใหม่
- **อนุมัติแล้ว** — ดาวน์โหลดไฟล์ Word ไปพิมพ์ ลงนาม แล้วส่งเอกสารให้เจ้าหน้าที่แผน
- **แบบร่าง** และ **อยู่ระหว่างดำเนินการ** (บอกว่ารอใครอยู่)
- ตัวเลขบนเมนู "โครงการของฉัน" = งานที่ต้องทำ + เอกสารลงนามครบที่ยังไม่ได้เปิด

## 💰 คุมงบและการเบิกจ่าย (แทนไฟล์ Excel คุมรายการเงิน)

1. **ตั้งวงเงินสาขา** — เมนู "จัดสรรงบสาขา" (เจ้าหน้าที่แผนแก้ได้, หัวหน้างานแผน/คณบดีดูได้) เลือกปีงบและแหล่งงบ แล้วใส่วงเงินของแต่ละสาขา
   - ชื่อสาขาต้องตรงกับช่อง `department` ของบัญชีอาจารย์ (ระบบดึงรายชื่อสาขาจากบัญชีผู้ใช้และโครงการให้แล้ว)
   - ตารางแสดง ผูกพัน (อัปโหลดสแกนแล้ว), รอลงนาม (เจ้าหน้าที่อนุมัติแล้ว ยังไม่ได้สแกน), เบิกจ่ายแล้ว และคงเหลือ — ตัวเลขคำนวณจากโครงการจริงทุกครั้ง
2. **อนุมัติโครงการ** — ถ้าโครงการทำให้สาขาใช้เกินวงเงินของแหล่งงบใด กล่องยืนยันจะแสดงคำเตือนพร้อมตัวเลข ยังอนุมัติได้ และระบบบันทึกไว้ในประวัติ (`BUDGET_OVER_CEILING`)
3. **อัปโหลดเอกสารที่ลงนามครบ (สแกน)** — ระบบให้ยืนยันโครงการและยอดเงินก่อน แล้วล็อกงบรายกิจกรรม × แหล่งงบ ตามรายการค่าใช้จ่ายในเอกสารที่ลงนาม และแจ้งอาจารย์อัตโนมัติ; แนบผิดกด "ย้อนการอัปโหลดสแกน" (ต้องใส่เหตุผล ทำได้ก่อนบันทึกเบิก) ไฟล์เดิมเก็บไว้เป็นหลักฐาน
4. **บันทึกการเบิกจ่าย** — หน้าโครงการ แท็บ "งบและการเบิกจ่าย": เลือกกิจกรรม ใส่วันที่ เลขที่ (เช่น 167/70) รายการ และจำนวนเงิน
   - เบิกเกินงบคงเหลือของกิจกรรมไม่ได้ (ถัวเฉลี่ยทุกรายการภายใต้กิจกรรมเดียวกัน)
   - บันทึกผิดกด "ยกเลิก" พร้อมเหตุผล รายการยังอยู่เป็นประวัติแต่ไม่นับยอด
   - บันทึกได้หลังอัปโหลดสแกนแล้วเท่านั้น; ถ้ามีรายการเบิกแล้ว ย้อนการอัปโหลดสแกนไม่ได้ (ต้องยกเลิกรายการเบิกก่อน)
   - อาจารย์เจ้าของโครงการเห็นงบและรายการเบิกแบบอ่านอย่างเดียว
5. **คุมงบโครงการ** — เมนู "คุมงบโครงการ" แสดงทุกโครงการที่อัปโหลดเอกสารลงนามครบแล้ว (ขออนุมัติ / ดำเนินการ / คงเหลือ / เปอร์เซ็นต์) กรองปีงบ แหล่งงบ สาขาได้ และกด "ส่งออก Excel" ได้ทีละแหล่งงบ — ไฟล์มีชีตหน้าหลัก ชีตรายโครงการ และชีตรายกิจกรรมสำหรับโครงการหลายกิจกรรม แบบเดียวกับไฟล์เดิมของคณะ
6. **ปิดโครงการ** — หลังอัปโหลดสแกนแล้ว เจ้าหน้าที่กด "ปิดโครงการ / คืนงบคงเหลือ" ในหน้าโครงการ ยอดเบิกจริงมาจากรายการเบิก งบที่เหลือคืนวงเงินสาขาอัตโนมัติ

   - ขอเกิน "คงเหลือ − ยอดที่ขอค้างอยู่" ไม่ได้
2. **เจ้าหน้าที่ดูคำขอ** ในแท็บ "เบิกจ่าย / ปิดโครงการ" ซึ่งมีป้าย "คำขอเบิกรอ N" ที่แถวของโครงการ แล้วเปิดไฟล์หลักฐาน จากนั้นเลือกได้ 2 ทาง
   - **บันทึกเบิก:** ใส่เลขที่ฎีกาและวันที่ แก้ยอดและรายการได้ ระบบจะลงทะเบียนการเบิกด้วยกฎเดิม (ห้ามเกินคงเหลือ)
   - **ตีกลับ:** ต้องใส่เหตุผล
3. **อาจารย์เห็นคำขอที่ถูกตีกลับ** ในหัวข้อ "คำขอเบิก/ขอปิดโครงการที่ถูกตีกลับ" ของ "งานของฉัน" และมีตัวเลขบนเมนู แก้แล้วส่งใหม่หรือยกเลิกได้
4. **อาจารย์กด "ขอปิดโครงการ"** พร้อมสรุปผลสั้น ๆ และแนบรายงานได้ถ้ามี ทำได้เมื่อไม่มีคำขอเบิกค้าง
5. **เจ้าหน้าที่ปิดโครงการ** ด้วยปุ่ม "ปิดโครงการ / คืนงบคงเหลือ" ตามเดิม หรือตีกลับคำขอปิด

มีคำขอเบิกค้างอยู่จะปิดโครงการและย้อนการอัปโหลดสแกนไม่ได้ ไฟล์หลักฐานเปิดได้เฉพาะคนที่เห็นโครงการนั้น

- **Backend:** `backend/services/disbursement_requests.py` ใช้คู่กับ `request_store.py`
- **หน้าเว็บ:** `web/src/components/plan/DisbursementRequests.tsx`
- **การออกแบบ:** `docs/superpowers/specs/2026-10-19-plan-disbursement-requests-design.md`

## 🧭 โครงสร้างของโมดูลงานแผน (Plan Workflow)

1. **ภาพรวม (Dashboard):**
   - แสดงตัวชี้วัดทางการเงิน 4 มิติ: งบประมาณทั้งหมด, ยอดผูกพันโครงการ, ค่าใช้จ่ายจริง, งบพร้อมจัดสรร
   - กราฟโครงสร้างยอดงบประมาณ
   - คิวงานรอพิจารณาแยกตามบทบาท (อาจารย์, ประธานสาขา, เจ้าหน้าที่แผน, คณบดี)
2. **Phase 1: จัดสรรงบประมาณ (Budget Setup):**
   - เมนูสำหรับเจ้าหน้าที่แผน: ตั้งค่างบประมาณประจำปี และกระจายงบลงสาขาวิชา (หมวดค่าตอบแทน / ค่าใช้สอย)
   - Real-time Unallocated calculation แจ้งเตือนเมื่อจัดสรรเกินกรอบวงเงิน
3. **Phase 2: เสนอโครงการใหม่ (Budget Proposal):**
   - แบบฟอร์มเสนอโครงการ 3 ขั้นตอน: ข้อมูลทั่วไป → แผนงบประมาณแจกแจง → แนบไฟล์ร่างโครงการ
   - รองรับการบันทึกแบบร่าง (Save Draft)
4. **รายการโครงการ & รายละเอียด (Projects Explorer & Detail):**
   - ค้นหาและกรองโครงการตามสถานะและสาขาวิชา
   - หน้ารายละเอียดโครงการ พร้อมสถานะเอกสาร (timeline ขั้นตอนลงนาม, เอกสารทุกฉบับ, ปุ่มตามบทบาท)
5. **งานตรวจสอบและอนุมัติ (Approval Workspace):**
   - คิว "รอตรวจ" และ "ติดตามเอกสาร" สำหรับเจ้าหน้าที่แผน (ประธานสาขา/คณบดีดูสถานะ)
   - Checklist ตรวจสอบตามระเบียบกระทรวงการคลัง
   - อนุมัติ (สร้างไฟล์ให้พิมพ์) / ตีกลับแก้ไข / ไม่อนุมัติ พร้อมระบุเหตุผล — ดูหัวข้อ Workflow เอกสารโครงการ
6. **Phase 4: คืนเงิน & ปิดโครงการ (Reconciliation & Closure):**
   - สรุปยอดเงินงบประมาณคงเหลือ
   - บันทึกคืนเงินทดรองจ่ายพร้อมแนบสลิป
   - รายงานสรุปผลลัพธ์โครงการและตัวชี้วัด KPI (จำนวนผู้เข้าร่วม, ผลประเมินความพึงพอใจ, ภาพกิจกรรม)
   - ปลดวงเงินเหลือคืนกองกลางคณะ
