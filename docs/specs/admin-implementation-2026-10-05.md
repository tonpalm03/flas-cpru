## การใช้งานที่เพิ่มหรือแก้ไข

1. ทุกหมวดมีดู/ดาวน์โหลด PDF ต้นฉบับ และอ่านข้อความต้นฉบับ
2. เพิ่มเอกสารจากฟอร์มเปล่าหรือดึงข้อมูลต้นแบบมาแก้ได้ โดยใช้วันที่ของรายการใหม่ ไม่ถือว่าวันที่/ชื่อผู้ลงนามในตัวอย่างเป็นข้อมูลปัจจุบัน
3. เพิ่มและแก้ไขใช้ฟอร์มเดียวกัน ครอบคลุมเนื้อหา สิ่งที่ส่งมาด้วย อ้างถึง ผู้ลงนาม ตำแหน่ง ที่อยู่ ผู้ประสานงาน และรายชื่อผู้รับเวียน
4. หนังสือเวียนภายนอกพิมพ์/ส่งออกแยกผู้รับโดยใช้เลขหนังสือร่วมกัน
5. แนบ เปลี่ยน และนำไฟล์จริงออก รองรับ PDF/DOCX/PNG/JPG สูงสุด 25 MB; ทดสอบส่วนนี้ด้วย Storage Emulator แล้ว ระบบจริงยังติดข้อจำกัด bucket ด้านล่าง
6. Word สร้างจากรายการที่เลือก ไม่ใช่ดาวน์โหลด Word ตัวอย่างเดิม; PDF ใช้หน้าต่างพิมพ์เฉพาะเอกสาร ไม่พิมพ์เมนู/ตารางทะเบียนติดไปด้วย
7. ค้นหา/กรองปีและสถานะ ส่งออก CSV เฉพาะผลกรอง พร้อม escape เครื่องหมายคำพูดและป้องกันสูตรในเซลล์
8. การเพิ่มทะเบียนและเพิ่ม counter อยู่ใน Firestore transaction เดียวกัน เลขไม่ถูกใช้เพียงเพราะเปิดฟอร์ม มี request ID ป้องกัน retry สร้างซ้ำ และ revision ป้องกันทับข้อมูลที่ผู้อื่นเพิ่งแก้
9. ฐานว่างแสดงว่าง ข้อผิดพลาดแสดงให้ทราบ ไม่ถอยไปบันทึก localStorage/mock แล้วแจ้งสำเร็จ; ล้าง cache ธุรการรุ่นเก่าครั้งเดียวเมื่อเปิดทะเบียน
10. ลบทะเบียนและไฟล์แนบได้ โดยเก็บ audit และไม่ลด counter เพื่อไม่ใช้เลขที่ออกไปแล้วซ้ำ

## สิทธิ์

ผู้ใช้ active อ่านทะเบียนได้ แอดมินหรือผู้มี `permissions: ['admin_documents']` เพิ่ม/แก้ไข/ลบได้ บทบาทหลักทั้ง 7 ไม่เปลี่ยน แอดมินยังใช้โมดุลได้โดยไม่ต้องเพิ่ม permission

เพิ่มกฎ Firestore/Storage สำหรับโมดุลนี้ ตรวจ active, ผู้สร้าง, ข้อมูลขั้นต่ำ, เลขจาก counter, ฟิลด์ทะเบียนที่ห้ามแก้ และ audit แบบเพิ่มอย่างเดียว ป้องกันผู้ใช้แก้ permission ตนเอง กฎชุดใหม่นี้ยังต้อง deploy ก่อนมีผลกับ cloud

สถานะเป็นทะเบียนปฏิบัติงาน ไม่ใช่ลายเซ็นดิจิทัลหรือการอนุมัติแทนคณบดี การเลือกลงนามแล้ว/ส่งแล้วต้องแนบหลักฐาน; เลือกยกเลิกต้องกรอกเหตุผล ยังไม่ได้เพิ่มระบบอนุมัติหลายชั้นซึ่งไม่ได้อยู่ใน 5 เมนูปัจจุบัน

## ข้อจำกัดระบบจริงที่ยังต้องจัดการ

**Firebase Storage:** ค่า environment ระบุ `flas-cpru.firebasestorage.app` แต่ API ตอบ 404 และการตรวจรายชื่อ buckets ของโปรเจกต์คืนว่าง จึงยังอัปโหลดไฟล์จริงไม่ได้ ต้องเปิดพื้นที่เก็บไฟล์และตั้งค่า bucket ก่อนใช้งานจริง ไม่ได้สร้าง bucket หรือผูก billing อัตโนมัติ

**Deployment:** ยังไม่ได้ deploy เว็บหรือ rules เนื่องจากมีการแก้โมดุลอื่นค้างใน workspace มาก่อนงานนี้ การ deploy ทั้งเว็บจะรวมการแก้เหล่านั้นด้วย ต้องตรวจ release ที่ต้องการก่อนเผยแพร่

**การตรวจรูปแบบ:** ใช้ PDF ต้นฉบับเป็นแหล่งอ้างอิง แต่เอกสารใหม่เป็นข้อความแก้ไขได้ จึงตัดบรรทัด/หน้าใหม่ตามความยาวข้อมูล ไม่ใช่การนำภาพต้นฉบับมาปิดทับ ชื่อบุคคลและข้อความจากการสกัดต้องตรวจทานก่อนลงนามใช้งานจริง

## เผยแพร่วันที่ 6 ตุลาคม 2569

ผู้ใช้อนุญาต deploy แล้ว เผยแพร่ Hosting และ Firestore rules ไปยัง flas-cpru สำเร็จที่ https://flas-cpru.web.app โดยใช้ production build ปัจจุบัน ซึ่งรวมการแก้โมดุลอื่นที่มีอยู่ใน workspace ด้วย

ตรวจ HTTP 200 และเทียบ SHA-256 กับไฟล์ build แล้วตรงกัน: หน้าหลัก หน้างานธุรการ ทั้ง 5 หมวด ตราครุฑบันทึกข้อความ และ PDF ต้นแบบบันทึกข้อความ การตรวจหลัง deploy เป็นการอ่าน ไม่เพิ่มหรือลบข้อมูลจริง

การ deploy Storage rules ไม่สำเร็จ: Firebase CLI ยืนยันว่าโปรเจกต์ยังไม่ได้ตั้งค่า Firebase Storage ต้องเปิดบริการที่ https://console.firebase.google.com/project/flas-cpru/storage แล้ว deploy storage.rules อีกครั้ง จึงยังไม่ถือว่าไฟล์แนบพร้อมใช้งานจริง ข้อความสถานะยังไม่ได้ deploy ในหัวข้อก่อนหน้านี้เป็นประวัติก่อนการอนุญาตรอบนี้

## แก้สิทธิ์บัญชีเก่าหลัง deploy

พบจากการตรวจโปรไฟล์จริงของบัญชีที่รายงานว่า role เป็น admin แต่ไม่มีฟิลด์ status (โปรไฟล์สร้างก่อนระบบสถานะบัญชี) กฎธุรการและ client ใหม่บังคับ active จึงปฏิเสธสิทธิ์ แก้ auth profile loader ทั้ง login และ reload ให้ใช้ active เฉพาะกรณีไม่มีฟิลด์ และใช้ Firestore isActiveUser ที่รองรับบัญชีเก่าเหมือนกติกาเดิม โดยต้องมี user document จริง ไม่เปลี่ยน role หรือเขียนสถานะลงข้อมูลจริง

ทดสอบ Emulator ผ่าน: บัญชี admin ที่ไม่มี status อ่าน/เพิ่ม/ลบ/แนบไฟล์ได้ และสถานะ suspended, pending_approval, archived ถูกปฏิเสธ ทดสอบ browser ด้วยโปรไฟล์ไม่มี status ผ่าน CRUD/reload/preview/Word ครบ 5 หมวด แก้ Storage rules ให้สอดคล้องไว้ด้วย แต่ยังต้องเปิด Storage ก่อน deploy กฎส่วนนั้น
เผยแพร่ตัวแก้สิทธิ์ Hosting และ Firestore rules สำเร็จแล้ว ตรวจหน้า login และ external-circular ตรงกับ build ใหม่หลัง deploy

## แก้รูปแบบบันทึกข้อความตามภาพเปรียบเทียบ
