## ชุด 0 — พื้นฐานระบบและความปลอดภัย

**ทำก่อนชุดอื่น** อ้างอิง CORE-01 ถึง CORE-12

```text
แก้ระบบฐานของ Faculty ERP ให้พร้อมต่อโมดุลจริง:
1. Firebase Auth เป็น source of truth ของ session และ profile
2. ปิดเส้นทางสมัคร/สร้างตัวเองเป็น admin และลบข้อมูลรับรองฝังใน client
3. ออกแบบ permission matrix: ผู้ยื่น เจ้าหน้าที่แต่ละฝ่าย ผู้ตรวจ ผู้อนุมัติ ผู้ดูแล
   แยกตำแหน่งบุคลากรออกจากสิทธิของงาน ไม่ให้ gov_officer มีทุกสิทธิอัตโนมัติ
4. Firestore/Storage rules ตรวจเจ้าของ หน่วยงาน สถานะ และฟิลด์ที่แก้ได้
   ผู้ใช้ทั่วไปแก้ role หรือผลอนุมัติของตัวเองไม่ได้
5. จัด schema กลาง/validation และ migration จาก seed ที่ชื่อฟิลด์ไม่ตรง types
6. master ปีงบ/ปีการศึกษา หน่วยงาน ผู้ลงนาม+วันมีผล และทะเบียนเลขเอกสาร atomic
7. attachment service แบบมีสิทธิ audit trail และ approval foundation
8. การบันทึกล้มเหลวต้องแจ้ง error/retry ไม่ fallback เป็นข้อมูลสำเร็จในเครื่อง
9. ตั้ง lint/CI และ test auth/rules/concurrent numbering
10. จัดคู่มือ env, staging, backup/restore และการใช้งานกับ static hosting
ส่ง schema, permission matrix, migration dry-run และผลทดสอบให้ตรวจ
อย่าแก้ครบทุกโมดุลรวดเดียวในชุดนี้ แต่ทำจุดเชื่อมให้ใช้ต่อได้จริง
```

**ตรวจรับ:** UAT-01 ถึง 04 ผ่าน; สิทธิทุกกลุ่มมีทั้ง positive/negative test; บัญชีทดสอบแก้ localStorage แล้วไม่ได้สิทธิสูงขึ้น; rules ยังคงใช้แอปได้ตามบทบาทที่อนุญาต; ไม่มีรหัสผ่านใน source/fixture; backup กู้ได้ใน staging

## ชุด 7 — ตรวจรับรวมและเตรียมเปิดใช้

```text
รันทดสอบ UAT-01 ถึง UAT-16 ตาม docs/audit/01-module-audit.md
ใช้หลายบัญชีและหลาย session ใน Emulator/staging ที่แทน role จริง
ตรวจทุก route/button/form ใน 04-menu-actions.md แล้วอัปเดตทะเบียนตามโค้ดใหม่
ตรวจ Word/PDF/Excel ของทุกประเภทกับต้นฉบับที่เจ้าของงานเลือก
ทดสอบ network fail, concurrent write, duplicate submit, read permission, restore และข้อมูลย้อนหลัง
ตรวจ Firebase Hosting deep-link/refresh โดยเฉพาะ static export กับ rewrite ปัจจุบัน
ตั้ง lint/CI ไม่โต้ตอบ และตรวจ build ของ commit ที่จะส่งมอบ
จัดคู่มือผู้ใช้รายบทบาท คู่มือ admin เปิดปี/ปิดปี migration rollback และ backup/restore
ส่งผลทดสอบพร้อมข้อบกพร่องที่ยังเหลือ ห้ามใส่ผ่านสำหรับรายการที่ไม่ได้ทดสอบ
ทำแผน cutover ที่มีผู้รับผิดชอบยอดตั้งต้นและชุดข้อมูลจริงที่ผ่านการทวน
ยังไม่ deploy production จนกว่าผู้รับผิดชอบอนุญาตการเปิดใช้
```
